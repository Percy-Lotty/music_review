# ✅ 提交前检查清单

每完成一个阶段的任务、准备提交代码时，按顺序过一遍。**全绿才提交。**

## 一、代码质量（每次提交前必做）

```bash
ruff check . --fix          # 静态检查并自动修复，期望输出 All checks passed!
black .                     # 统一格式，期望输出 left unchanged
python manage.py check      # Django 配置检查，期望输出 no issues
python manage.py test       # 测试，期望输出 OK（改动了逻辑时必跑；纯模板/文案可跳过）
```

顺序别反：先 `ruff --fix` 再 `black`。`--fix` 改动了文件的话，`git diff` 扫一眼再提交。

## 二、git 提交

- [ ] 先 `git status` 看清动了哪些文件，**不要习惯性 `git add -A`**
- [ ] 一次提交只装一件事：重构、测试、数据分开放
- [ ] 提交信息用类型前缀：
      `feat` 新功能 / `fix` 修 bug / `refactor` 重构 / `test` 测试 /
      `docs` 文档 / `chore` 杂务 / `perf` 性能 / `style` 纯格式
- [ ] `git push origin main`（加速器偶发 HTTP 502，重试即可）

## 三、特殊场景

### 在 admin 里改了数据之后

数据存在 `db.sqlite3`（被 `.gitignore` 忽略，永远不会进 Git）；Git 只跟踪手工快照 `reviews/fixtures/seed_data.json`。

- [ ] 只想自己看：什么都不用做，admin 即改即生效
- [ ] 想让仓库里也有这份数据：

```bash
python manage.py dumpdata reviews --indent 2 -o reviews/fixtures/seed_data.json
git diff reviews/fixtures/seed_data.json      # 确认只有预期改动
git add reviews/fixtures/seed_data.json
git commit -m "chore: 更新示例数据（说明改了什么）"
git push origin main
```

### 新机器 / 新克隆

```bash
pip install -r requirements.txt -r requirements-dev.txt
python manage.py migrate
python manage.py loaddata seed_data    # 恢复 13 张专辑、乐评与用户评分
```
