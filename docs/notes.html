一、Git 和 GitHub 配置

1.1 设置 Git 身份

git config --global user.name "Percy-Lotty"
git config --global user.email "2467252796@qq.com"

什么意思：
- 这就像给 Git 填了个“工牌”，以后每次保存代码快照时，Git 都知道是你干的。
- --global 意思是全局生效，电脑上所有项目都用这个身份，设一次就行。

1.2 生成 SSH 密钥，连接 GitHub

ssh-keygen -t ed25519 -C "2467252796@qq.com"
cat ~/.ssh/id_ed25519.pub

什么意思：
- 生成了一对“钥匙”：公钥（放在 GitHub 上）和私钥（留在你电脑里）。
- 以后你往 GitHub 上传代码，GitHub 靠这把钥匙确认是你本人，不用每次输密码。
- 设了无密码，因为开发阶段频繁推送，每次都输密码太烦。以后想加密码可以随时加。

三、Django 项目创建

3.1 创建项目

django-admin startproject music_review
cd music_review

python manage.py startapp reviews

项目和应用的通俗区别：
- 项目 = 整个网站
- 应用 = 网站里的一个功能模块（比如“专辑管理”就是一个应用）
- 一个项目可以装多个应用

3.3 注册应用

在 music_review/settings.py 里找到 INSTALLED_APPS，加上 'reviews'。

为什么要注册：告诉 Django“我这个项目用了这个应用”，不然 Django 不认识它，数据库迁移时也不会管它。

3.4 写第一个页面

视图（reviews/views.py）——决定“返回什么内容”：

from django.http import HttpResponse

def home(request):

应用自己的路由（reviews/urls.py，这个文件要自己新建）——决定“什么网址走什么视图”：

from django.urls import path

四、数据库

4.1 初始化数据库

python manage.py migrate

Django 自带了一些内置功能（用户系统、后台管理等），这条命令帮它们建好数据库表。

4.2 数据库文件

Django 默认用 SQLite，数据库存在项目根目录的 db.sqlite3 文件里。这个文件不能当文本打开，它有自己的格式，只能通过 Django 来操作。

4.3 数据库报错排查

问题：执行 migrate 时报 disk I/O error，提示无法读写磁盘。

排查：
1. 确认没有其他程序打开 db.sqlite3
2. 尝试删除数据库文件——失败，提示“访问被拒绝”
3. 发现是 D 盘路径有权限限制

解决：把整个项目从 D 盘搬到 C 盘桌面，问题消失。以后所有操作都在 C 盘这个目录下进行。

4.4 终端使用技巧

  • 终端输出很长停住时（末尾有冒号 :），按 Q 键退出
  • 停止开发服务器按 Ctrl+C
  • 改已有代码后服务器会自动重启，但新建文件后需要手动重启

五、数据模型

5.1 Album 模型（专辑）

在 reviews/models.py 里写：

import requests
from django.db import models
from django.core.validators import MinValueValidator, MaxValueValidator

class Album(models.Model):
    title = models.CharField(max_length=200)
    artist = models.CharField(max_length=200)
    release_date = models.DateField()
    cover_url = models.URLField(blank=True)
    genre = models.CharField(max_length=100, blank=True)
    label = models.CharField(max_length=100, blank=True)

    # 乐评人相关字段（每张专辑只有一份）
    # 评分范围 0-100，使用 validators 限制
    critic_score = models.IntegerField(
        null=True, 
        blank=True,
        validators=[MinValueValidator(0), MaxValueValidator(100)]
    )
    critic_review = models.TextField(blank=True)
    critic_name = models.CharField(max_length=100, blank=True)
    critic_published_at = models.DateField(null=True, blank=True)

    def __str__(self):
        return f"{self.title} - {self.artist}"

    def fetch_cover_from_itunes(self):
        """从 iTunes API 获取专辑封面（无需 API 密钥）"""
        url = 'https://itunes.apple.com/search'
        params = {
            'term': f'{self.artist} {self.title}',
            'media': 'music',
            'entity': 'album',
            'limit': 1
        }
        try:
            response = requests.get(url, params=params, timeout=5)
            response.raise_for_status()
            data = response.json()
            if data['resultCount'] > 0:
                cover_url = data['results'][0]['artworkUrl100'].replace('100x100', '1000x1000')
                self.cover_url = cover_url
                self.save()
                return cover_url
        except Exception as e:
            print(f"iTunes 获取封面失败：{e}")
        return None

字段说明：

字段 类型 说明
title CharField 专辑名
artist CharField 艺人名
release_date DateField 发行日期
cover_url URLField 封面链接（blank=True 表示可空）
genre CharField 风格
label CharField 厂牌
critic_score IntegerField 乐评人评分（0-100），含验证器
critic_review TextField 乐评人文章
critic_name CharField 乐评人姓名
critic_published_at DateField 乐评发布时间

关于验证器（Validators）：
- MinValueValidator(0) 和 MaxValueValidator(100) 确保乐评人评分必须在 0 到 100 之间
- 如果后台输入 -5 或 150，Django 会报错提示，不会存入数据库
- 验证器在模型层和表单层都会生效

5.2 Review 模型（普通用户评分）

class Review(models.Model):
    album = models.ForeignKey(Album, on_delete=models.CASCADE, related_name='reviews')
    score = models.IntegerField(validators=[MinValueValidator(1), MaxValueValidator(10)])
    reviewer_name = models.CharField(max_length=100, blank=True)
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        constraints = [
            models.UniqueConstraint(fields=['album', 'reviewer_name'], name='unique_user_review_per_album')
        ]

    def __str__(self):
        name = self.reviewer_name or "匿名用户"
        return f"{name} - {self.album.title} - {self.score}分"

字段说明：

字段 类型 说明
album ForeignKey 外键，指向 Album。related_name='reviews' 表示通过专辑查评分时用 album.reviews.all
score IntegerField 评分（1-10），含验证器
reviewer_name CharField 评论者名字
created_at DateTimeField 创建时间，auto_now_add=True 自动记录

唯一约束（UniqueConstraint）：
- fields=['album', 'reviewer_name']：同一用户对同一张专辑只能有一条评分
- 如果用户“张三”给《Daydream》打了 9 分，再打一次 7 分会被数据库拒绝
- 要改分只能修改已有记录，不能新增

六、视图（views.py）

from django.shortcuts import render, get_object_or_404
from django.db.models import Avg
from .models import Album

def home(request):
    albums = Album.objects.all()
    return render(request, 'reviews/home.html', {'albums': albums})

def album_detail(request, album_id):
    album = get_object_or_404(Album, id=album_id)

    # 计算普通用户的平均分
    user_reviews = album.reviews.all()
    avg_score = user_reviews.aggregate(Avg('score'))['score__avg']

    # 保留一位小数，如果没有评分就设为 None
    if avg_score is not None:
        avg_score = round(avg_score, 1)

    return render(request, 'reviews/album_detail.html', {
        'album': album,
        'avg_score': avg_score,
    })

函数说明：

函数 作用 对应 URL
home 查出所有专辑，渲染首页 /
album_detail 根据 album_id 查一张专辑，计算平均分，渲染详情页 /album/<id>/

album_detail 详细拆解：

album = get_object_or_404(Album, id=album_id)
  • 根据 id 查专辑，找不到自动返回 404 页面
user_reviews = album.reviews.all()
avg_score = user_reviews.aggregate(Avg('score'))['score__avg']
  • album.reviews.all()：通过 related_name='reviews' 反向查所有用户评分
  • aggregate(Avg('score'))：计算 score 字段的平均值，返回 {'score__avg': 8.5}
  • ['score__avg']：从字典里取出平均值
if avg_score is not None:
    avg_score = round(avg_score, 1)
  • 如果没有评分，avg_score 是 None，不处理
  • 如果有评分，保留一位小数（8.45 → 8.5）

七、后台管理（admin.py）

7.1 AlbumAdmin

from django.contrib import admin
from django.utils.safestring import mark_safe
from .models import Album, Review

@admin.register(Album)
class AlbumAdmin(admin.ModelAdmin):
    list_display = ('title', 'artist', 'release_date', 'critic_score', 'critic_name', 'critic_published_at', 'genre', 'label', 'cover_preview')
    fields = ('title', 'artist', 'release_date', 'cover_url', 'genre', 'label', 
              'critic_score', 'critic_review', 'critic_name', 'critic_published_at')

    def cover_preview(self, obj):
        if obj.cover_url:
            return mark_safe(f'<img src="{obj.cover_url}" width="50" height="50" style="object-fit: cover;" />')
        return "无封面"
    cover_preview.short_description = '封面'

    def save_model(self, request, obj, form, change):
        super().save_model(request, obj, form, change)
        if not obj.cover_url and obj.title and obj.artist:
            cover_url = obj.fetch_cover_from_itunes()
            if cover_url:
                self.message_user(request, f'成功获取封面图片！')

配置说明：
- list_display：列表页显示的列
- fields：表单页显示的字段（及顺序）
- cover_preview：自定义方法，显示封面缩略图
- save_model：保存时自动获取封面

7.2 自定义评分范围筛选器

class ScoreRangeFilter(admin.SimpleListFilter):
    title = '评分范围'
    parameter_name = 'score_range'

    def lookups(self, request, model_admin):
        return (
            ('low', '低分 (1-3分)'),
            ('medium', '中分 (4-7分)'),
            ('high', '高分 (8-10分)'),
        )

    def queryset(self, request, queryset):
        if self.value() == 'low':
            return queryset.filter(score__range=(1, 3))
        if self.value() == 'medium':
            return queryset.filter(score__range=(4, 7))
        if self.value() == 'high':
            return queryset.filter(score__range=(8, 10))
        return queryset
组成部分 作用
title 右侧边栏显示的文字
parameter_name URL 参数名（如 ?score_range=low）
lookups 返回下拉菜单的选项（内部值, 显示文字）
queryset 根据选中的值，过滤数据

score__range=(1, 3) 的含义：
- 双下划线 __ 表示“字段查找”（Field lookup）
- range 是 Django 内置的查找类型，表示闭区间
- 等价于 score__gte=1 AND score__lte=3

7.3 ReviewAdmin

@admin.register(Review)
class ReviewAdmin(admin.ModelAdmin):
    list_display = ('album', 'score', 'reviewer_name', 'created_at')

配置说明：

十、重要概念

10.1 单下划线 vs 双下划线

符号 用途 示例
_（单下划线） Python 命名规范（蛇形命名） reviewer_name、release_date
__（双下划线） Django ORM 特殊语法 album__title（跨表）、score__range（字段查找）

10.2 blank=True vs null=True

属性 作用范围 说明
blank=True Django 表单验证 允许表单不填
null=True 数据库层面 允许存 NULL

规律：
- 文本字段（CharField、TextField）：只需要 blank=True
- 数字/日期字段（IntegerField、DateField）：需要 null=True, blank=True

10.3 Validators（验证器）

验证器 作用
MinValueValidator(n) 值不能小于 n
MaxValueValidator(n) 值不能大于 n

使用场景：
- 乐评人评分：validators=[MinValueValidator(0), MaxValueValidator(100)]
- 用户评分：validators=[MinValueValidator(1), MaxValueValidator(10)]
